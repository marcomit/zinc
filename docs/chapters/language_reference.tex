\section{Types}

Zinc is statically typed: every expression has a type that is fully known at
compile time.

\subsection{Primitive Types}

\begin{center}
\begin{tabular}{ll}
\toprule
Type & Description \\
\midrule
\zn{u0}                             & Empty type (\texttt{void} equivalent) \\
\zn{u1}                             & Boolean (\texttt{true} or \texttt{false}) \\
\zn{u8}, \zn{u16}, \zn{u32}, \zn{u64} & Unsigned fixed-width integers \\
\zn{i8}, \zn{i16}, \zn{i32}, \zn{i64} & Signed fixed-width integers \\
\zn{f32}, \zn{f64}                  & Floating-point numbers \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Compound Types}

\begin{center}
\begin{tabular}{ll}
\toprule
Type & Description \\
\midrule
\texttt{*T}       & Pointer to \texttt{T} \\
\texttt{[n]T}     & Fixed-size array of \texttt{n} elements \\
\texttt{[]T}      & Slice (pointer + length) \\
\texttt{(T1, T2)} & Tuple (at least 2 fields) \\
\texttt{R(A, B)}  & Function type: returns \texttt{R}, takes args \texttt{A}, \texttt{B}, \ldots \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Literals}

\begin{itemize}
    \item \textbf{Integers:} Decimal \texttt{123}, hexadecimal \texttt{0xdeadbeef},
          binary \texttt{0b1010101}
    \item \textbf{Floats:} Standard \texttt{3.14}, scientific \texttt{1e-10}
    \item \textbf{Booleans:} \texttt{true}, \texttt{false}
    \item \textbf{Null pointer:} \texttt{none}
    \item \textbf{Chars:} Not supported.
    \item \textbf{Strings:} \texttt{*char}, content between double quotes.
          Supported escapes: \texttt{{\textbackslash}n \textbackslash t \textbackslash r \textbackslash" \textbackslash 0}
\end{itemize}

\subsection{Arrays and Slices}

Array sizes must be compile-time constants.
\begin{lstlisting}[style=zinc, caption={Arrays and slices}]
[5]i32 nums = [1, 2, 3, 4, 5] // Typed declaration with literal
arr := [1, 2, 3, 4, 5]        // Type inferred from literal

// Slicing produces a []T (pointer + length)
mid  := arr[1:4]  // indices 1..3
head := arr[:3]   // indices 0..2
tail := arr[3:]   // indices 3..end
\end{lstlisting}

A slice compiles to a struct carrying a pointer and a length.
The \texttt{.len} field is available on both arrays and slices.
Mutations through a slice propagate to the underlying array.

\begin{lstlisting}[style=zinc, caption={Iterating with .len}]
i := 0
for i < arr.len {
    arr[i] = i
    i = i + 1
}
\end{lstlisting}

\subsection{Tuples}

Tuples group heterogeneous values into a single unnamed struct.
They require at least two elements.

\begin{lstlisting}[style=zinc, caption={Tuple construction and access}]
pair   := (12, "hello")
triple := (21, "hello", 3.14)

u32 n = triple.0   // access by index
\end{lstlisting}

Tuples are the idiomatic way to return multiple values:

\begin{lstlisting}[style=zinc, caption={Multiple return values}]
divmod :: (u32, u32)(u32 a, u32 b) {
    return (a / b, a mod b)
}
\end{lstlisting}

\subsection{Structs}

\begin{lstlisting}[style=zinc, caption={Struct declaration and construction}]
Vector2 :: struct {
    f32 x
    f32 y
}
origin := Vector2{ x: 0.0, y: 0.0 }
\end{lstlisting}

Fields are accessed with \texttt{.}. Pointer types are auto-dereferenced on
field access, so \texttt{ptr.field} and \texttt{(*ptr).field} are equivalent.

\subsection{Enums}

Enums are tagged unions (sum types) that can carry per-variant data.
Each variant is a struct prefixed by a \texttt{u8} discriminant tag.

\begin{lstlisting}[style=zinc, caption={Enum declaration and construction}]
Shape :: enum {
    Square(f32)     // single f32 payload
    Rect(f32, f32)  // two f32 payloads
    None            // no payload
}

square := Shape::Square(10.0)
rect   := Shape::Rect(12.0, 10.0)
\end{lstlisting}

\section{Variables}

Variables live on the stack and are always mutable.
The type can be stated explicitly or inferred from the right-hand side.

\begin{lstlisting}[style=zinc, caption={Variable declarations}]
i32 val = 0   // explicit type
other := 10   // inferred type
\end{lstlisting}

\textbf{Destructuring} binds struct fields or tuple elements directly to names:

\begin{lstlisting}[style=zinc, caption={Destructuring}]
// Struct: bind fields by name, optionally with a rename
{x, y}             := point
{x: px, y: py}     := point

// Tuple: bind by position
(first, second)    := pair
\end{lstlisting}

\section{Functions}

\subsection{Declarations}

Functions follow C-like syntax.
The arrow form \zn{->} is shorthand for a single-expression body.

\begin{lstlisting}[style=zinc, caption={Function declarations}]
add :: u32 (u32 a, u32 b) {
    return a + b
}

mul :: u32 (u32 a, u32 b) -> a * b

main :: i32 () {
    return add(10, mul(12, 3))
}
\end{lstlisting}

\subsection{Receiver Methods}

The \zn{for} block attaches methods to a type.
The named binding after the type is the implicit \emph{self} argument.

\begin{lstlisting}[style=zinc, caption={Receiver methods}]
i32 self :: for {
    add :: u32 (u32 b) -> self + b
}

*i32 ptr :: for {
    incr :: u0 () {
        *ptr = *ptr + 1
    }
}

main :: i32 () {
    val := 10
    val.add(5)
    10.add(20)

    p := &val
    p.incr()
    return 0
}
\end{lstlisting}

\subsection{Static Functions}

Omitting the receiver binding creates a static (namespace-scoped) function
called with \zn{Type::name()} syntax.

\begin{lstlisting}[style=zinc, caption={Static functions}]
Counter :: struct {
    i32 count
}

Counter :: for {
    new :: Counter() -> Counter{ count: 0 }
}

main :: i32 () {
    c := Counter::new()
    return 0
}
\end{lstlisting}

\subsection{Capabilities}

A capability is a contextual dependency declared in a second parameter list
after the main one. The caller does not pass it explicitly; instead it is
threaded automatically from a surrounding \zn{with} block.

\begin{lstlisting}[style=zinc, caption={Capability declaration and use}]
use <core::mem>

allocBuf :: *u8 (u64 size)[Allocator alloc] {
    return alloc.alloc(size)
}

main :: i32 () {
    with heap := Allocator::heap() {
        buf := allocBuf(1024) // alloc injected automatically
    }
    return 0
}
\end{lstlisting}

Capabilities are propagated transitively: a function that calls another
capability-requiring function inherits the requirement automatically.

\begin{lstlisting}[style=zinc, caption={Transitive capability}]

new :: *u8 ()[Allocator allocator] {
    return allocator.alloc(sizeof MyStruct)
}

transitive :: *u8()[Allocator] { // Unnamed capability
    return new() // Capability is passed implicitly
}

main :: i32 () {
    with _ := Allocator::heap() {
        transitive()
    }
}
\end{lstlisting}
Transitive capabilities are often unused in the function itself but just passed to other functions (like in this example the \texttt{transitive} function doesn't use the \texttt{Allocator}). So the capability name can be omitted.

\subsection{Foreign Declarations}

Foreign declarations import C functions for use as ordinary Zinc functions.
Variadic C functions are supported with \texttt{...}.
Related functions can be grouped under a named namespace.

\begin{lstlisting}[style=zinc, caption={Foreign declarations}]
foreign printf :: u0 (*char, ...)

libc :: foreign {
    malloc  :: *u8  (u64)
    free    :: u0   (*u8)
}

main :: i32 () {
    printf("Hello, world!\n")
    buf := libc::malloc(1024)
    libc::free(buf)
    return 0
}
\end{lstlisting}

\section{Control Flow}

\subsection{Conditionals}

\begin{lstlisting}[style=zinc, caption={if / else}]
if x > 0 {
    // positive
} else if x == 0 {
    // zero
} else {
    // negative
}
\end{lstlisting}

\zn{if} is also an expression when written with \zn{->}.
Branches must produce values of the same type.

\begin{lstlisting}[style=zinc, caption={Inline if expression}]
i32 abs = if x >= 0 -> x else -> -x

// Nesting is allowed
i32 max3 = if a > b -> if a > c -> a else -> c
           else     -> if b > c -> b else -> c
\end{lstlisting}

\subsection{Loops}

Zinc uses \zn{for} for both C-style and while-style loops.

\begin{lstlisting}[style=zinc, caption={Loop forms}]
// While-style
i := 0
for i < 10 {
    i = i + 1
}

// C-style
for j := 0; j < 10; j = j + 1 {
    // ...
}
\end{lstlisting}

\zn{break} exits the innermost loop; \zn{continue} skips to the next iteration.

\begin{lstlisting}[style=zinc, caption={break and continue}]
for i < 10 {
    i = i + 1
    if i == 5 { break }
    if i mod 2 == 0 { continue }
    // only odd values below 5 reach here
}
\end{lstlisting}

\subsection{Defer}

\zn{defer} schedules a statement to run when the enclosing scope exits,
in last-in first-out order.

\begin{lstlisting}[style=zinc, caption={defer}]
{
    buf := libc::malloc(1024)
    defer libc::free(buf)   // runs at end of block

    // ... use buf ...
}
\end{lstlisting}

\subsection{Update Operator}

The update operator \zn{:} reads a mutable location, transforms its value
through an expression, and writes the result back. It replaces the family of
compound-assignment operators (\texttt{+=}, \texttt{-=}, \texttt{*=}, \ldots)
with a single, uniform mechanism that also extends naturally to method calls.

\subsubsection*{Syntax}

\begin{center}
\begin{tabular}{ll}
\toprule
Form & Desugars to \\
\midrule
\texttt{x : \emph{op} \emph{expr}} & \texttt{x = x \emph{op} \emph{expr}} \\
\texttt{x : \emph{unary\_op}}      & \texttt{x = \emph{unary\_op} x}      \\
\texttt{x : f(\emph{args})}        & \texttt{x = f(x, \emph{args})}       \\
\texttt{x : .method(\emph{args})}  & \texttt{x = x.method(\emph{args})}   \\
\bottomrule
\end{tabular}
\end{center}

The left-hand side must be a mutable location: a variable, a field access, a
pointer dereference, or a subscript. The right-hand side must be one of the
four forms above; plain assignment uses \zn{=} instead.

\subsubsection*{Basic usage}

\begin{lstlisting}[style=zinc, caption={Update operator --- arithmetic}]
count : + 1          // count = count + 1
price : * 1.08       // price = price * 1.08
ratio : / total      // ratio = ratio / total
remaining : 100 -    // ERROR: leading operand not allowed
\end{lstlisting}

For non-commutative operations where the current value must appear on the
right-hand side, write a plain assignment instead:

\begin{lstlisting}[style=zinc, caption={Non-commutative case --- use plain assignment}]
x = 1 - x           // explicit, unambiguous
x = 100 / x
\end{lstlisting}

\subsubsection*{Unary forms}

\begin{lstlisting}[style=zinc, caption={Update operator --- unary}]
flag  : not          // flag  = !flag
mask  : ~            // mask  = ~mask
\end{lstlisting}

\subsubsection*{Function and method forms}

When the RHS is a function call, the current value is passed as the first
argument. When the RHS is a method call (dot form), it becomes the receiver.

\begin{lstlisting}[style=zinc, caption={Update operator --- calls}]
buf    : compress()        // buf    = compress(buf)
name   : .to_lower()       // name   = name.to_lower()
value  : clamp(0, 100)     // value  = clamp(value, 0, 100)
config : merge(defaults)   // config = merge(config, defaults)
\end{lstlisting}

\subsubsection*{Evaluation guarantee}

The left-hand side is evaluated exactly once, even when it contains a
side-effecting expression such as a subscript with a computed index.

\begin{lstlisting}[style=zinc, caption={Left-hand side evaluated once}]
buf[next_slot()] : + 1
// Equivalent to:
//   __addr := &buf[next_slot()]   // next_slot() called once
//   *__addr = *__addr + 1
\end{lstlisting}

\subsubsection*{Type rule}

The expression produced by the RHS must have the same type as the
left-hand side. Using \zn{:} to change a variable's type is a compile-time
error; use a new declaration with \zn{:=} instead.

\begin{lstlisting}[style=zinc, caption={Type mismatch is a compile error}]
i32 count = 0
count : .to_string()   // ERROR: RHS produces *char, expected i32
\end{lstlisting}

\section{Type Casting}
To cast a type zinc uses the \zn{as} keyword after the expression:
\begin{lstlisting}[style=zinc, caption={Type casting}]
foreign malloc :: *u8 (u64)
main :: i32 () {
    *MyStruct = malloc(sizeof MyStruct)// implicit casted from *u8 to *MyStruct
    buff := malloc(sizeof MyStruct) as *MyStruct //explicit cast
    myStruct := buff as *u8
}
\end{lstlisting}

\section{Visibility}
There are just two level of visibility: by default when you declare a something it is visible only in that file. by adding the \zn{pub} keyword that symbol becomes global. Other files can import that file by using the \zn{keyword} filename (A \texttt{.zn} is added at the end). To include a nested file you can use the :: to navigate into a directory and \zn{super} to go up the directory.
